# Editing sources for readability

Read the root [`CLAUDE.md`](../CLAUDE.md) first: every change must pass `python3 tools/objcheck.py check`.

## Layout

| Directory | What | Readability work |
|---|---|---|
| `P2/` | clean engine code, real classes (`bis.cpp`, `dmas.cpp`, …) | the target style |
| `hand/` | hand-matched functions, one per file, local struct declarations with pads | phases 2–3 |
| `auto/` | raw m2c output (`M2C_FIELD`, `temp_v0`) compiled as **C** | phases 2–3 |
| `splicewrap/` | generated by `tools/gen_splicewrap.py` | rename callees only; regenerate rather than hand-edit |
| `lib/` | Sony SDK libraries | out of scope, leave as is |

`.c` files compile as C, `.cpp` as C++ (`-x c++`); in `.cpp` files, functions called by address name are declared
inside `extern "C" { … }` so the symbol is the plain name.

## Rules

- Rename with `tools/rename.py`, never by hand: it keeps `config/` and file names in sync.
- A change that only touches comments, names or whitespace never changes the code, but run objcheck anyway.
- Type changes can change code generation (`int` vs `short`, `const`, member order, signedness, unions,
  declaration order of locals). If objcheck reports `DIFFERS`, revert or find the declaration that matches.
- Do not remove register pins, `__asm__` statements or odd declaration orders without checking: most exist only to
  get the match. Keep the comment that explains why; add one if it is missing.
- Keep a function's file named after its symbol (`rename.py` does it). Grouping functions into original translation
  units is phase 5; do not start it ad hoc.
- Shared types go in `include/` (one header per class/subsystem). Never edit a shared header without running
  `objcheck.py check --all`: every includer may change.

## Shared types (phase 2)

- Headers in `include/`: `clock.h` (CLOCK, g_clock), `dl.h` (DL, DLE, DLI), `util.h` (LM, RGBA), `cref.h` (CRef), `vu0.h` (quadword/float helpers, `vu0_qword`), `mat.h` (MATRIX3/MATRIX4 as rows or floats), `vecmat.h` (VU_FLOAT, VU_VECTOR), `vtable.h` (VTE), `vec.h` (VECTOR with w), plus the older
  `bis.h`, `vec.h`, `mat.h`, `dmas.h`, `gifs.h`, `vifs.h`, `heap.h`, `qw.h`.
- Field names: when Sly 1 names a field (`sly1/include/*.h`), use its name (DL `head`/`tail`, DLI `m_pdl`…, RGBA
  `bRed`…), so the two projects can be read side by side; otherwise use the name that explains the code that
  reads or writes the field, with the offset in a comment.
- Headers must compile as C and C++: `struct X {…};` plus `typedef struct X X;` under `#ifndef __cplusplus`;
  globals without `extern "C"` (g++ 2.95 does not mangle variables).
- Migrate users with `tools/migrate_struct.py STRUCT HEADER`, then `tools/objcheck.py check`; revert
  (`git checkout`) every file that fails to build or changes code, and fix those by hand later.
- Helpers: before writing a local `static inline` for a VU0 op or a min/max/clamp, look in `include/vu0.h`;
  `tools/dedupe_inlines.py` replaces exact local copies.
- `XxxCidNN` names (`InitCid48`, `LoadCid43FromBrx`) are virtual methods whose role is known from the vtable slot
  but whose class (cid NN in `docs/CLASSES.md`) is not named yet. When a class is identified, rename them all
  (`tools/rename.py`) and add the class to `CLASSES` in `tools/name_vslots.py`.
